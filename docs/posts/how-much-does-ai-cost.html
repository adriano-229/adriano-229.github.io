How Much Does AI Cost?

I've just read an article about how AI providers charge for usage. Here's what I understood.

How it works

When you send a prompt to an AI model, the provider charges you based on the number of tokens processed.

There are three main costs:

  • Input tokens: the tokens sent to the model.
  • Output tokens: the tokens generated by the model.
  • Cached tokens: previously processed input tokens that can be reused at a reduced price.

Prices are usually expressed in dollars per million tokens (MT).

Let's define the following variables:

  • Input price: I dollars per MT.
  • Output price: O dollars per MT.
  • Cache write price: W dollars per MT.
  • Cache read price: R dollars per MT.
  • Input length: X MT.
  • Output length: Y MT.

Without caching, the cost of a single request is:

Cost = X times I + Y times O

Notice that the model's maximum context length is not necessarily the number of tokens billed. You pay for the tokens actually processed, according to the provider's pricing rules.

What happens when you send a second prompt? Will you pay X times I again for the input?

Not necessarily! Some providers offer prompt caching, which allows previously processed input tokens to be reused at a lower price.

There are two important operations:

  • Cache write: Storing input tokens for potential reuse. This may cost more than regular input processing.
  • Cache read (cache hit): Reusing cached tokens at a reduced price.

A cache read is possible only if the relevant content has already been cached and the cache is still valid.

Think of caching as temporarily storing a reusable portion of your prompt. The provider keeps that content available for a limited time, potentially reducing the cost of subsequent requests.

For example, a provider might offer a five-minute cache lifetime. The exact duration and pricing depend on the provider and model.

Example

Suppose we make 15 requests, each processing 30,000 input tokens and generating an average of 1,500 output tokens.

Assume the following prices:

  • Input price: 2 dollars per MT.
  • Output price: 10 dollars per MT.
  • Input length: 30,000 / 1,000,000 = 0.03 MT.
  • Output length: 1,500 / 1,000,000 = 0.0015 MT.
  • Cache write price: 1.25 times the input price = 2.50 dollars per MT.
  • Cache read price: 0.1 times the input price = 0.20 dollars per MT.

With caching

Assume the first request writes the input to the cache, while the remaining 14 requests successfully reuse all cached input tokens.

The first request costs:

0.03 times 2.5 + 0.0015 times 10 = 0.09 dollars

The remaining 14 requests cost:

14 times (0.03 times 0.2 + 0.0015 times 10) = 0.294 dollars

Therefore, the total cost with caching is 0.384 dollars.

Without caching

Every request processes the input at the regular input price:

0.03 times 2 + 0.0015 times 10 = 0.075 dollars per request

For all 15 requests:

15 times 0.075 = 1.125 dollars

How much do we save?

The absolute savings are:

1.125 - 0.384 = 0.741 dollars

The percentage reduction is approximately 65.9%.

In this example, caching reduces the total cost by approximately 65.9%.

Final thoughts

Caching can significantly reduce costs when the same context is reused across multiple requests. However, cached content is available only for a limited time, cache writes may cost more than regular input tokens, and only part of a prompt may be eligible for caching.

Also, remember that a model's maximum context length is a limit, not the number of tokens automatically billed for every request.

This is a simplified example, but the main idea is straightforward: if you repeatedly send the same context, prompt caching can save you money.
